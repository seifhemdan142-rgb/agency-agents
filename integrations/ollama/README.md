# Ollama Integration

Converts every Agency agent into an [Ollama](https://ollama.com) Modelfile. Each
agent becomes a directory containing a `Modelfile` that sets a base model
(`FROM`) and the agent persona as the `SYSTEM` prompt, ready for
`ollama create`.

## Installation

### Prerequisites

- [Ollama](https://ollama.com/download) installed and running
- The base model pulled locally (default `llama3.1`):
  ```bash
  ollama pull llama3.1
  ```

### Install

```bash
# Generate integration files (required on fresh clone)
./scripts/convert.sh --tool ollama

# Stage Modelfiles into ~/.ollama/agency-agents/
./scripts/install.sh --tool ollama
```

Installing only stages the Modelfiles — Ollama models are created explicitly, so
nothing is registered behind your back.

## Usage

### Register one agent

```bash
ollama create agency-frontend-developer \
  -f ~/.ollama/agency-agents/frontend-developer/Modelfile

ollama run agency-frontend-developer "Review this React component for performance issues"
```

### Register all of them

```bash
for d in ~/.ollama/agency-agents/*/; do
  ollama create "agency-$(basename "$d")" -f "$d/Modelfile"
done
```

Each model takes no extra disk for weights — it reuses the layers of the base
model and only stores its own system prompt.

### List and remove

```bash
ollama list | grep '^agency-'
ollama rm agency-frontend-developer
```

## Choosing a base model

Generated Modelfiles start `FROM llama3.1`. Override it at conversion time:

```bash
OLLAMA_BASE_MODEL=qwen2.5:14b ./scripts/convert.sh --tool ollama
```

Or edit the `FROM` line of a single Modelfile before `ollama create`. Any model
in your local library (or on the registry) works — agents with long, detailed
personas do better on models with a large context window.

## File layout

```
~/.ollama/agency-agents/frontend-developer/
└── Modelfile        # FROM <base> + SYSTEM <persona>
```

```
# Frontend Developer — generated by The Agency (scripts/convert.sh); edits are overwritten.
# Expert frontend developer specializing in modern web technologies...
FROM llama3.1

SYSTEM """
# Frontend Developer Agent Personality
...
"""
```

The `SYSTEM` block is fenced with `"""` — the only multiline fence Ollama's
Modelfile grammar accepts. The grammar has no escape for that fence, and some
personas embed Python docstrings written with `"""`, which would close the block
early. The converter rewrites those inner fences to `'''`, which is equivalent
in Python, so the snippets keep working.

## Notes

- Regenerate after editing agents: `./scripts/convert.sh --tool ollama`. Models
  already created keep their old prompt until you re-run `ollama create`.
- `OLLAMA_AGENTS_DIR` overrides the install destination.
- `--link` symlinks Modelfiles instead of copying, so regeneration propagates.
